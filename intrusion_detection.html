📋 Abstract

This project implements an intrusion detection system (IDS) for IoT devices using XGBoost machine learning. The system trains on the EdgeIIoT dataset and provides a Flask web dashboard for real-time network traffic monitoring. It achieves high accuracy in distinguishing normal traffic from attacks but has limitations in detecting zero-day vulnerabilities—a known challenge with supervised learning approaches.

🎯 Project Goals

  • Build an ML-based IDS capable of detecting multiple attack types in IoT traffic
  • Create an interactive dashboard displaying real-time traffic analysis
  • Evaluate performance using comprehensive classification metrics
  • Assess feasibility for real-world deployment scenarios

🔍 Background & Motivation

IoT Security Challenges

IoT networks present unique security problems:

  • Devices run on limited hardware with minimal security configurations
  • Multiple communication protocols (MQTT, CoAP) create complexity
  • Default credentials and unpatched firmware are widespread
  • Traditional security tools are too resource-intensive for IoT environments

Why Machine Learning?

ML algorithms can learn normal traffic patterns and automatically detect anomalies, finding subtle patterns that manual analysis would miss. XGBoost and similar ensemble methods are particularly effective due to their ability to handle noisy data and imbalanced datasets.

📊 Dataset & Preprocessing

Source: EdgeIIoT dataset (ML-EdgeIIoT variant from Kaggle)
Features: 32 network packet features including ARP, ICMP, HTTP, TCP, UDP, DNS, MQTT, and Modbus TCP fields

Data Pipeline

1. Feature Selection

Removed identifying fields (IP/MAC addresses, timestamps) to ensure model generalizes across different devices.

2. Data Cleaning

Deleted rows with missing values, removed duplicates, and converted categorical features to numerical format.

3. Class Balancing

Applied random undersampling on normal traffic to address class imbalance and prevent majority-class bias.

4. Feature Scaling

Applied Min-Max scaling (0–1 range) to prevent high-magnitude features from dominating training.

🤖 XGBoost Model Configuration

Why XGBoost?

  • Excellent performance with imbalanced data
  • Provides feature importance scores for interpretability
  • Handles non-linear patterns effectively
  • Fast inference suitable for real-time applications

Hyperparameters (Optimized via GridSearchCV)

  • Algorithm: Binary Classification
  • Number of Trees: 100
  • Learning Rate: 0.1
  • Max Depth: 5
  • Min Child Weight: 1
  • Subsample: 0.8
  • Feature Subsample: 0.8

Training Pipeline

  1. Load EdgeIIoT dataset
  2. Split data (80% train, 20% test)
  3. Apply feature scaling
  4. Balance training set
  5. Train XGBoost classifier
  6. Evaluate on holdout test set

💡 Key Insights

📡 MQTT Protocol Critical

MQTT-related features dominate attack detection, indicating IoT devices using MQTT are identifiable attack vectors.

🎯 High Attack Precision

99% precision on test set means very few false alarms—critical for operational feasibility.

📊 Good Generalization

Similar performance on unseen test data suggests the model captures genuine attack patterns, not noise.

🔍 Explainable Alerts

Feature importance helps operators understand why traffic was flagged, building trust in automated systems.

⚠️ Limitations & Challenges

1. Zero-Day Attack Vulnerability (Critical)

The model can only detect attacks matching its training data. Novel attack methods are invisible to supervised learning approaches. Example: If an attacker invents a new IoT malware variant not in EdgeIIoT, the system treats it as normal traffic.

2. Dataset Specificity

The model is trained specifically on EdgeIIoT network characteristics. Performance may degrade in different network environments without retraining.

3. Detection-Only

The system alerts on suspicious traffic but doesn't automatically block connections, isolate devices, or trigger automated responses. Manual intervention is required for containment.

🔮 Future Improvements

1. Anomaly Detection Layer

Implement unsupervised methods (Isolation Forest, Autoencoders) to catch zero-day attacks by detecting statistical deviations from normal traffic baselines.

2. Active Response Module

Automated IP blacklisting, device isolation protocols, and alert escalation workflows for proactive defense.

3. Continuous Learning

Periodic retraining on new data, feedback loops from security analysts, and federated learning for multi-site deployments.

4. Explainability Enhancement

SHAP values for per-sample explanations, confusion case analysis, and attack attribution (identifying specific attack types).
